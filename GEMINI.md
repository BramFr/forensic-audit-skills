# Forensic Audit Guidelines (Gemini)

@./CLAUDE.md

## Skills

This extension ships five agent skills in `skills/`. Gemini loads them on demand when the request matches their description:

- `forensic-audit`: audit and fact-check any AI-generated output.
- `forensic-security-audit`: scoped security audit of a codebase (vulnerabilities, secrets, dependencies, configuration): find, prove, fix and re-test.
- `forensic-site-audit`: crawl a web app, test every feature against the live backend, capture and judge screenshots.
- `docs-first-planner`: turn a wish, feature or bug into an audited, approved plan stored in `./docs` (uses `forensic-audit` in its audit phase, and switches to `forensic-security-audit` plus a security baseline in `./docs/security` when the wish is about security).
- `first-principles-architect`: domain-neutral intake and design engine (7 dimensions, systems analysis, closed verification loop, clean delivery) for anything that must be built, designed, tuned or solved, delivered without tracking it in `./docs`. It always starts by researching the principles of the request with `forensic-audit`; `docs-first-planner` does the same before every plan. `docs-first-planner` embeds it in full as phase 1.5.

## Companion MCP Servers (`mcp/web-search` & `mcp/context-compressor`)

When the `web-search` MCP server is enabled (eagerly or lazy-loaded), prefer its `search_website(query_or_url="...", auto_open_top=1)` tool (or batch calls `search_website(queries_or_urls=[...], auto_open_top=1)` / inline `"open: <query>"` up to 10 items per call with persistent SQLite WAL + RFC 9111 `ETag` caching, session-delta block re-slicing, and a `<= 9.500 B` batch byte-budget) over built-in search/fetch tools: pass a concise search query (**4–6 core terms**, run sequentially or in batches of 2–5) with `auto_open_top=1` (or `open:`) to get DuckDuckGo results (`🔍 SNIPPET`) and open the highest-ranked primary authority source in **1 turn** (`🔎 SOURCED`), or pass the primary source URL (`http://` or `https://`, HTML or PDF, via `search_website(query_or_url="https://...", filter_query="<keywords>")` or inline `"https://... <keywords>"` on long pages/catalogs/PDFs to stay `<= 10.240 B` inline without truncating primary source context) to read the document in Markdown (`🔎 SOURCED`), and run **Step 2B Adversarial Disconfirmation & Triple Actuality/Typology Checks** (existence at time $t$, binding obligation vs. guideline, higher authority) on uncertain or legacy claims. **Whenever `forensic-audit` (or any audit skill) and `web-search` are used, always check first whether `./docs/index.md` exists with a `## Search keywords` section (via `compress_context(file_path="docs/index.md", section="Search keywords")`):** if present and the request is about the project or its domain, you MUST pick 1 to 3 matching keywords from `## Search keywords` per query (`{selected keywords} {query}`: 1–2 leading vision/scale priority terms from the start of the list for architecture/UI/scale/workflow queries, or 1–2 **technical/methodological domain terms** such as `primary-source-verification`, `ISO-NEN-IEC`, `IETF-RFC`, `NIST-SP-800`, `OWASP-ASVS`, `Python-stdlib` for external protocol/RFC/standard/scientific queries without prepending abstract vision words like `zero-trust` or `no-fake-green`, stripping search-operator punctuation like `+`, and never 0 keywords — sending 0 project keywords counts as `🚫 NOT SEARCHED`); if not present (e.g. a standalone question outside the project or its domain), proceed with the normal search flow without project keywords. When an audit requires `>= 8` web searches/scrapes (such as `docs-first-planner`'s combined 7 orthogonal D1–D7 layer searches + 10 P1–P10 claim searches after Phase 0 and Phase 1, decomposed across 3–6 sub-topics and 4 lifecycle safeguards for composite wishes), prefer delegating the web-research batch (**Batch Prompting** `arXiv:2511.04108` without hard token caps, using **DAST/CoD** concise Chain-of-Draft for D1–D7 and deep reasoning for P1–P10) to a `research`/`self` subagent that opens the primary sources in full and performs a **Zero-Trust Context-Purge**, returning compact `#schema:` tables (including **Control Point 1: 2 pros and 2 cons from subject to solution**, followed by **Control Point 2: 2 pros and 2 cons from subject to solution**, the **Simplicity Ladder** YAGNI -> DRY -> Stdlib -> Native -> Existing Deps -> Minimal Code + LBYL, and Hick's Law Smart Defaults + `<details>` Progressive Disclosure in the grill options, decisions and plan/pre-delivery check), after which the main agent continues directly in the same flow with Phase 2.5, Phase 3 (Grill), Phase 3.5 and Phase 4. An `ERROR:` response from `search_website(query_or_url="https://...")` never counts as `🔎 SOURCED`—try another primary URL from the results or fall back to `🔍 SNIPPET` and log it in the Negative Declaration.

Use `compress_context` from `mcp/context-compressor` across all phases: (1) **Phase 1 & Skill Progressive Reading** (`filter_query="<keywords>"` on `docs/index.md` for tiered `#schema:` projection; default **slim plan-read** on `docs/<cat>/NN-slug.md` which keeps 2-column `Decisions` + `Scope (Out)` and omits heavy sections unless requested via `section="Scope,Approach,Acceptance criteria"` or `section="--all"`; and section-scoping on `SKILL.md`/reference files such as `section="Principles,Pre-build use (principles research)"` when delegating to research or execution subagents instead of full-file `read_file` calls), (2) **Phase 2 Subject/File Audit** (`section="--signatures"` or `section="func1,func2"` on `.py`/`.ts`/`.js`, `section="key"` on `.json`/`.yaml`/`.toml`, and when auditing `>= 3` files in depth, delegate a read-only `research` subagent with a compressed Context Pack returning `#schema:point|status|file_line|evidence`), and (3) **Phase 4/5 Execution-Subagent Isolation**: when writing or modifying any file or deliverable (even 1 line), always delegate the edit to a fresh execution subagent (`invoke_subagent` / `Agent` tool) and build its lossless **Subagent Context Pack** with `compress_context` (`--signatures` + target symbols/sections + scoped `.md` section / `MODULE.md`, Pipe-DSV `#schema:` for `N >= 2` flat rows/tables, or `JSON_COMPACT` for nested/sparse data; never use lossy word-pruning or parallel edits on the same file).
